**st's runs show in stui.** When st runs on the same machine, stui reads its local server (127.0.0.1, GET only) and shows st's runs and agents beside its own, marked `(st)`. Output, attach, CI, copy, `r` and `d` work on them; `ctrl-d` on one of st's workers says `this is st's run: use st ui`. A pane both see is listed once. If st's server is not running or does not answer within a second, stui shows only its own runs. `st.read: false` in config.yaml turns it off. Other machines stay in `st ui`.

**Copy what you see, without the frame.** A mouse selection takes the borders and columns with it; these keys copy only the content, as plain text:

- `y` on a row copies its value (a session's name, `session:index`, a pane's id, a run's name, a CI run's URL), `Y` the whole row, tab-separated.
- In a pane's output, `v` starts a line selection, `j` `k` `g` `G` extend it and `y` copies it; `y` with no selection copies the whole output, not only what is on screen.
- `z` shows the output alone on the screen, no frame, for your terminal's own mouse selection.

The text goes to the terminal's clipboard (OSC 52, or `tmux load-buffer -w` inside tmux) and to `pbcopy`, `wl-copy`, `xclip` or `clip.exe` when the machine has one.

Plugins can no longer bind `y` or `Y`; none of the published ones did.
