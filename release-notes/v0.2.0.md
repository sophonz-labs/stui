stui shows your Claude and Codex limits again, takes plugins, keeps its settings in a file, and draws its logo in the header.

**Usage limits.** stui asks Anthropic and OpenAI for your plan limits every few minutes, with the login Claude Code and Codex already keep on this machine: the same request their own `/usage` makes. The token goes to its own provider and nowhere else, and stui never writes, logs or refreshes it. `stui usage poll off` turns it off. A per-model weekly limit is named by its model ("weekly sonnet").

**Plugins.** A plugin is one `plugin.json` that brings another CLI into stui: a view that turns a command's output into a table, keys on its rows and on your agents' panes, and `:` commands. The same plugins work in tmui. Install one by name from [sophonz-labs/tui-plugins](https://github.com/sophonz-labs/tui-plugins):

```sh
stui ext install gh-prs
```

The installer prints every command the plugin will run and asks first. `:ext` lists what is installed; a plugin can never take one of stui's own keys. (`stui plugin` is still what puts the orchestration skills into Claude Code and Codex.)

**Settings.** `~/.config/stui/config.yaml`, as k9s keeps its own: the logo, the header, colour, the refresh rate, the first view, plugins. `stui config edit` makes the file with every default in it, `:config` shows what is in effect, and saving it applies it. `ctrl-e` hides the header.

**Orchestration** with nothing running now says how to start a run, and that a machine with st keeps its runs in `st ui`. stui needs no st, no account and no relay.
